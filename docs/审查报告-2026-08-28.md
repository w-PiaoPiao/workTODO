## 一、高严重度（2 项，均已实证复核，建议立即修复）

### H1. 打包版开机自启 100% 失效，且每次开机弹编译错误对话框
- **位置**：`app/services/autostart_service.py:54`
- **问题**：startup.vbs 以 `encoding="utf-8-sig"`（带 BOM）写入，而 Windows Script Host 不识别 UTF-8 BOM——实测 `cscript` 对带 BOM 的 .vbs 报 `Microsoft VBScript compilation error: Invalid character (1,1)`。开发模式不走 VBS 分支，故此 bug 只在打包版（项目主要分发形态）暴露：开启自启后每次登录弹错误对话框、应用不自启。
- **修复**：改 `encoding="utf-16"`（WSH 原生 Unicode 格式，实测中文路径/内容均正常）。修复后在打包版实测「开启自启 → 重启」链路。

### H2. 标签筛选可进入 UI 内无法恢复的死锁状态
- **位置**：`app/controllers/app_controller.py:499-502` + `app/views/tag_filter_row.py:82-84`
- **问题**：被筛选的标签从所有活跃待办中消失（删除待办或编辑标题去掉 `#标签`）后，`_active_tag` 不复位：① 还有其他标签时 chips 无高亮但过滤仍生效；② 无标签残留时整行隐藏，主列表显示"还没有待办事项"——数据还在，用户却以为全丢了，且无任何 UI 手段清除筛选，只能重启。
- **修复**：`_refresh_views` 中加 3 行校验：`if self._active_tag and self._active_tag not in tags: self._active_tag = ""`。

## 二、中严重度（约 20 项，按主题分组）

### A. 数据安全（5 项）— `app/models/`
1. **`todo_store.py:52-59` flush 固定"先 todos 后 archived"顺序**：归档动作中途写盘失败+退出 → 该条待办在两个文件里都不存在（永久丢失）。修复：按最后操作方向决定写盘顺序（丢失窗口变重复窗口）+ 加载后按 id 双侧去重。
2. **`todo_store.py:61-71`、`note.py:99-102` save_* 先赋缓存/清脏标记再写盘**：写盘失败后内存与磁盘永久分叉，flush 永不重试。修复：先写盘成功再赋缓存/清脏（同文件 `flush()` 已是正确顺序）。
3. **`json_io.py:70-77` 损坏备份为固定名覆盖式 .bak 且全程静默**：第二次损坏抹掉第一次备份；更糟的是损坏→返回空列表后，用户任意一次写操作就把原文件合法覆盖，"最后一次好数据"无任何副本。修复：时间戳备份名保留 N 份 + 损坏时 UI 明确告知并提供恢复入口。
4. **`json_io.py:49-67` 原子写入无 fsync**：掉电/蓝屏时 `os.replace` 只保证名字切换原子，不保证内容落盘，可能产生 0 字节文件（恰好落入上一条的静默清零路径）。修复：`write → flush → os.fsync → close → replace`；顺带修掉 `PermissionError` 冗余捕获与 `unlink()` 可能掩盖原始异常的问题。
5. **`json_io.py:33-39` load_json_list 不捕 OSError**：数据文件被杀毒/同步盘临时锁定时，异常穿透 `AppController.__init__` → 启动即崩。修复：捕获后短重试，仍失败走隔离+提示路径。

### B. 正确性（8 项）— 控制器与视图
6. **`app_controller.py:510-521` 归档恢复未失效搜索索引**：`id(self._todos)` 身份判定 + store"恢复是原地 append"→ 特定操作序列后该条目永远搜不到。修复：恢复成功分支补 `_invalidate_search_index()`；根治方案是 store 维护显式版本号取代 `id()` 判定。
7. **`expanded_view.py:726-771` 置顶动画幽灵图层残留**：快速连点两次置顶时 `anim.stop()` 不发射 `finished`，上一轮 ghost 卡片截图永久冻结在屏幕上。修复：ghost 与 anim 成对保存，重启前先 `deleteLater`。
8. **`archive_dialog.py:35-38` 恢复后对话框不刷新**：打开时快照列表，恢复后条目仍显示，再点"恢复"静默无反馈，按钮像坏了。修复：恢复成功回调 `dialog.remove_item(id)` 刷新。
9. **`main_window.py:317-324` 启动恢复窗口位置无屏幕边界校验**：换显示器/改分辨率后 140×140 小窗可能整体落在屏幕外，托盘"显示"只 raise 不重定位，用户无法找回。修复：恢复后调 `_snap_to_screen_edge()` 或 `screenAt` 校验回退默认位置。
10. **`pet_view.py:98-99` 桌宠去白底缓存键只用 `src.stem`**：内置与用户素材同名、或同目录 `cat.png`/`cat.jpg` 共享缓存条目，会加载到完全不相干的形象图。修复：缓存名加入来源目录标识与扩展名。
11. **`pet_view.py:461-489` 双份 `_movie` 状态**：`load_pet()` 提前 return 路径下画布持有已 `deleteLater` 的 QMovie，下次 `paintEvent` 抛 `RuntimeError`。修复：movie 生命周期收敛到 PetCanvas 单处管理。
12. **`custom_tooltip.py:96-108` 长文本 tooltip 无有效宽度上限**：单行长标题可撑到 4000px 跨屏（全局 QSS 的 QToolTip max-width 对自绘 QFrame 不生效）。修复：测量上限降到 ~480px 强制换行。
13. **`progress_widget.py:95-99` 每次刷新强制重置进度展开态**：展开某卡片进度后，任何一次数据刷新就自动收起，与 ExpandedView 的展开记录脱节。修复：刷新后按记录恢复展开态。

### C. 健壮性与防御（2 项）
14. **`todo_item.py:228-248`、`note.py:39-50` `from_dict` 不防"键存在但值为 null/类型错"**：`"id": null` → 多条数据 `id=None` 互相覆盖；`tags` 为字符串被逐字符拆分。修复：统一 `_get_str(data, key, default)` 工具，id 非法一律重新生成。
15. **`drag_drop_manager.py:164-175` 拖拽自动滚动按事件频率逐步 setValue**：长列表滚动过快不可控。修复：QTimer 30ms 节流。

### D. 工程化（4 项）
16. **依赖全部只有 `>=` 下限无锁定**：打包产物不可复现，重新打包随时拉最新版。修复：核心依赖 `==` 精确固定或引入 lock 文件。
17. **仓库卫生**：根目录 3 个未跟踪调试脚本（`_debug_indicator.py`、`_debug_stick.py`、`sandbox_pytest_fix.py`——后者全局改写 `pathlib.Path.mkdir`，文件头自称"不入库"）；`app/resources/pets/` 下 3 个未跟踪处理残片 PNG——`build.ps1` 会把它们打进发布包且用户可见为额外桌宠选项。修复：调试脚本删除或移 `tools/dev/`（进 .gitignore），残片 PNG 移出 resources。
18. **`.gitignore` 缺口**：`.pytest-basetmp-dock/`（0o700 权限导致 git status 持续报警告、`git add .` 不干净）、`data/pets/`（用户素材与 `_processed` 缓存会入库）未覆盖。另有 `.ruff_cache/` 建议一并补充。
19. **测试 offscreen 声明分散且用 `setdefault`**：`conftest.py` 未统一设置，带显示器的环境下 `test_dock_indicator.py:68` 的 `QCursor.setPos` 会真实移动用户鼠标。修复：`conftest.py` 顶部（Qt 导入前）强制 `os.environ["QT_QPA_PLATFORM"] = "offscreen"`。
