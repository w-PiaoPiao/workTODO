### Bug 修复：QToolTip 黑底看不清 → 改白底

**现象**：卡片标题/进度悬浮显示完整文本时，弹窗是黑色背景（Windows 原生样式），看不清。

**根因**（三层定位）：
- 第一层：`AppTheme.global_qss()` 之前只在 `MainWindow.setStyleSheet()` 调用
  - Windows 下 `QToolTip` 是**独立顶层窗口**，不继承 MainWindow 的 QSS
  - 修复：把全局 QSS 提升到 `QApplication.setStyleSheet()` 级别
- 第二层（用户反馈仍黑底）：即使 QSS 在 QApplication 级别，Windows
  仍用 GDI 画 tooltip 窗口，QSS `background` 只影响 Qt 内部
  background，OS 仍按系统 tooltip 样式绘制
  - 修复：通过 `QPalette` 的 `ToolTipBase`/`ToolTipText` 角色设置
    Windows 系统级 tooltip 颜色
- 第三层（用户反馈仍黑底）：Windows 11 对 tooltip 的 GDI 渲染非常强硬，
  QSS 和 QPalette 都无效
  - **最终修复**：完全绕过原生 tooltip，自定义白底 tooltip 窗口

**最终方案**：新增 `app/views/custom_tooltip.py` + `main.py` 安装
- `_TooltipEventFilter` 安装在 `QApplication` 上，拦截所有 `QEvent.ToolTip`
- 阻止原生 tooltip（返回 `True`）
- 用 `CustomTooltip`（白底 `QFrame`）自己显示
- 支持：8 秒自动隐藏、鼠标移出/点击/按键/窗口失焦隐藏、限制在屏幕内、多行文本
- 保留 QApplication QSS + QPalette 作为 fallback/通用样式

**修改**：
- 新增 `app/views/custom_tooltip.py`
- `main.py`：
  - `app.setStyleSheet(AppTheme.global_qss())`
  - `app.setPalette(palette)` 设置 `ToolTipBase=#FFFFFF`, `ToolTipText=#1A1A1A`
  - `install_custom_tooltip(app)`

**验证**：
- `app.notify(label, QHelpEvent)` 触发 tooltip ✓
- CustomTooltip 可见、文本正确、QSS 含 `#FFFFFF` 白底 ✓
- 鼠标移出/点击/隐藏时 tooltip 消失 ✓
- 启动 app 无错，退出无 RuntimeError ✓

### Bug 修复：文本溢出（彻底解决）

**昨日遗留**：todo_card 和 progress_widget 多次尝试修复文本溢出（commit
ef8e4eb / d3e41ec / a715d88），均告失败。

**根因（系统性）**：
- elision 逻辑塞在 widget lifecycle 里（resizeEvent + QTimer.singleShot + setMaximumWidth）
- 多个时机互相触发，时序难抓（layout 未完成时 self.width() 错误）
- magic number `self.width() - 132` 按钮状态变化时算错
- setMaximumWidth 强制约束触发 layout → resize 循环
- 3 次失败符合 "3+ fixes 失败 = 架构问题" 模式，应当问题架构而非再加 hack

**架构修复**：创建 `app/views/elided_label.py` — `ElidedLabel(QLabel)` 子类。

核心设计：
- `paintEvent` 实时用 `fontMetrics.elidedText()` 算，永远基于正确的当前 width
- `sizeHint/minimumSizeHint` 返回 `QSize(0, h)` → layout 把所有剩余空间全分配给我们
  （默认 QLabel.sizeHint 是完整文本宽度，会抢空间）
- 完整文本存 `_full_text`，`text()` 覆盖返回完整（方便外部访问/调试）
- `setFullText()` 触发 `update()` 重新 paint
- tooltip 自动同步完整文本

**替换**：
- `todo_card._title_label`: QLabel → ElidedLabel
- `progress_widget._make_entry_row`: 进度文本 QLabel → ElidedLabel，删除 eventFilter 和 _text_labels 字典
- `archive_dialog._make_archive_card`: 进度摘要 QLabel → ElidedLabel

**收益**：
- 删除 ~30 行 fragile 逻辑（`_elide_title`, `resizeEvent`, `QTimer.singleShot`, `eventFilter`, `_text_labels`）
- 删除 magic number 132
- 删除 3 处 import（QTimer, QEvent, QFontMetrics, 部分 QSizePolicy）
- resize 时自动重新省略（paintEvent 自动触发）
- 长文本 100% 不溢出（已用 offscreen 测试验证：204px 宽度 45 字符 → 12 字符 + …）

**验证**（offscreen QApplication）：
- 短文本：完整显示 ✓
- 长文本：paintEvent 实时省略，含 `…` ✓
- setFullText：触发 update 重绘 ✓
- 父窗口缩放 800→200：title label 宽度 644→44，elision 自动适应 ✓
- 全 app 启动 / 添加 / 搜索 / 折叠：均无错误 ✓

### Bug 修复：删除确认弹窗黑底

**现象**：点击删除后 QMessageBox 确认框纯黑背景，仅显示一个蓝色圆形图标。

**根因**：全局 QSS 的 `QWidget { color: #1A1A1A; }` 规则使所有 widget

**修复**：在 `theme.py` 的 `global_qss()` 中新增 `QMessageBox` 样式
- 背景白底 `#FFFFFF`
- 标签文字 `#1A1A1A`
- 按钮边框+圆角+悬停效果

**修改**：`app/views/theme.py` — global_qss() 尾部加 QMessageBox 规则块

**验证**：应用启动无错 ✓

### Bug 修复：CMD 窗口弹窗报错 '不是内部或外部命令'

**现象**：启动软件时同时弹出一个 CMD 窗口，显示乱码命令名和
"不是内部或外部命令" 错误。

**根因**：`run.bat` / `run_hidden.bat` 以 **UTF-8 无 BOM + LF 换行**
保存。Windows cmd.exe 按 **GBK(936)** 解析文件，UTF-8 中文注释的
字节码被误解析为命令名 → cmd 报错找不到该"命令"。

**修复**：
- 注释改为纯英文（ASCII → 任何代码页解析一致）
- 行尾从 LF 改为 CRLF（Windows 标准）
- 删除中文注释（UTF-8 中文字节在全 ASCII 下无歧义）

**验证**：启动无 CMD 报错窗口 ✓
