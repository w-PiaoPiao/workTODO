# 开发日志 2026-09-02

## 修复：上次展开拉高后，中部再展开面板被顶出屏幕一半

### 现象（用户报告）

1. 展开面板（桌宠）→ 用户把手柄拉高（如 1000px，尺寸被记忆）。
2. 折叠回桌宠（140×140）。
3. 把桌宠拖到屏幕中央附近。
4. 再次展开 → 面板上半部分（含标题栏）被顶出屏幕顶部，界面几乎不可用。

### 根因（`app/views/main_window.py`）

旧展开逻辑（`_choose_expand_anchor` + `_animate_size` 锚点角）用**桌宠左上角 + 完整展开尺寸**
判定展开方向：

- `over_right = x + w > 屏幕右`、`over_bottom = y + h > 屏幕底`：桌宠在屏幕中部时，
  只要记忆尺寸大，两个条件必然成立 → 判为 `bottom_right` 锚点；
- `bottom_right` 锚点把窗口**左上**移动（`x = 桌宠x + 桌宠宽 - 目标宽`、
  `y = 桌宠y + 桌宠高 - 目标高`），面板越往上、左拉出屏幕——这正是"顶出屏幕一半"的来源。

锚点展开（步骤 8.5）只保证"不瞬移"，从不保证"完整可见"；加入尺寸记忆后，
记忆尺寸可能远大于桌宠到屏幕边缘的余量，越界就成了常态。

### 改动（`app/views/main_window.py`）

把"按目标尺寸选锚点角"改为"**按桌宠位置逐轴钳制，整窗只做最小位移**"：

1. **`_visible_expand_delta(pet_geo, target, screen)`（新，取代 `_choose_expand_anchor`）**
   - 逐轴独立：面板相对桌宠"同左上角"先展开，再检查是否越界。
   - 越出**右/下缘**时：优先把面板右/底缘**锚到桌宠右/底缘**（贴边展开、无瞬移，与原行为一致）；
     若面板比桌宠到对侧屏幕的空间还大（锚定必然顶出对侧），则改为**贴屏幕边缘留
     `SCREEN_MARGIN`**——完整可见优先。
   - 桌宠本身悬出屏幕（异常位置）→ 拉回屏幕内留边距。
   - 返回值是左上角位移 `QPoint`；尺寸被 `_effective_expanded_size` 预先钳到
     可用区 - 2×margin，因此钳制结果必完整可见。
2. **`expand()` / `collapse()`**：状态改为记录 `_expand_delta`（本次展开的位移），
   折叠时用 `-delta` 反向移回 → 桌宠回到原位，展开/折叠严格可逆（不再依赖锚点对称）。
3. **`_animate_size`**：入参由 `(w, h, anchor, base_geo)` 改为
   `(w, h, delta, base_geo)`，左上角 = base 左上角 + delta。展开/折叠共用。

行为影响：

- 屏幕中央/顶部等"记忆尺寸放不下"的位置展开 → 面板被整体收进屏幕（本次 bug 修复）；
- 贴右/底缘展开 → 右/底缘仍然原位锚定（原有贴边无瞬移语义保留）；
- 折叠 → 与展开等量反向位移，桌宠必回原位。

### 测试
