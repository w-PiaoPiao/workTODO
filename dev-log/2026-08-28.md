     ① 其他条目仍带此标签 → 条目消失、筛选保持（原意图保留）
     ② 标签整体消失 → 筛选自动复位、列表恢复全量（新增 `test_title_edit_resets_vanished_tag_filter`）

3. **归档恢复补搜索索引失效**（`_on_restore_item`）

## 第二批修复（数据安全专项）

### 完成事项

1. **原子写入补 fsync**（`app/models/json_io.py` `atomic_write_json`）
   - 原实现 write_text 后直接 replace：掉电/蓝屏时 os.replace 只保证名字切换原子，
     内容可能未持久化 → 空文件/半截文件落入"损坏→静默清零"路径
   - 改为 open → write → flush → os.fsync → close → replace；
     顺带修复：PermissionError 是 OSError 子类（冗余捕获）、清理分支 unlink 可能抛错掩盖原始异常
     （改 missing_ok=True + 独立 try）

2. **save_* 写盘优先**（`todo_store.save_todos/save_archived`、`note.NoteStore.save_notes`）
   - 原实现先赋缓存/清脏标记再写盘：写盘失败后内存与磁盘永久分叉，
     flush 因不再脏而永不重试（同文件 flush() 本是正确的"先写后清"，两套顺序并存系疏漏）
   - 统一为先写盘成功再赋缓存/清脏

3. **方向化 flush + 跨列表去重**（`todo_store`）
   - 原实现固定"先 todos 后 archived"：归档动作中途写盘失败+退出 → 条目在两个文件里都不存在（永久丢失）
   - 新增 `_last_cross_op` 记录最后跨侧操作方向（archive/restore，auto_archive_old 归入 archive），
     flush 双侧都脏时**先写结果侧**：最坏结果从"丢失"降为"重复"
   - 新增 `_dedupe_cross_lists` 加载兜底：同一 id 双侧出现时保留归档侧、
     原地剔除活跃侧（保持列表对象同一性，先前返回的引用同步生效）并标脏纠正

4. **损坏隔离备份改造**（`json_io.backup_corrupted`）
   - 原实现固定名覆盖式 `.json.bak`：第二次损坏抹掉第一次备份；
     且损坏→返回空列表后，用户任意一次写操作就把原文件合法覆盖，"最后一次好数据"无副本，全程静默
   - 改为带时间戳副本 `xxx.json.corrupt.<时间戳>.bak`（保留 `CORRUPT_BACKUP_KEEP=5` 份，自动清理最旧）
   - `load_json_list` 新增 `on_problem(kind, path, detail)` 回调；TodoStore/NoteStore 记录到 `problems`，
     控制器 `_load_data` 后经 `_notify_store_problems()` 明确告知用户（损坏已隔离/文件不可读），
     并提示可从「备份」菜单恢复——消除静默清零

5. **启动读取容错**（`json_io.load_json_list`）
   - 原实现不捕 OSError：数据文件被杀毒/同步盘临时锁定时异常穿透控制器构造 → 启动即崩
   - 改为短重试（3 次 × 递增等待）后仍失败则记 problems、以空数据启动并 UI 告知

6. **from_dict 空值/类型防御**（`todo_item.TodoItem/ProgressEntry`、`note.Note`）
   - 原实现 `dict.get(key, default)` 不防"键存在但值为 null/类型错"：
     `"id": null` → 多条数据 id=None 在按 id 匹配的 update/delete 时互相覆盖；
     tags 为字符串被逐字符拆成单字标签；created_at/content 等非 str 穿透
   - 新增 `_get_str` / `_get_id` 工具统一收口：非 str 取默认、id 缺失/空/非法一律重新生成；
     progress/tags 非 list 归空；title 非 str 归空串（随后被空标题剔除逻辑过滤）

## 第三批修复（视图正确性 + 工程化收尾）

### 完成事项

1. **置顶动画幽灵图层残留**（`expanded_view.py` `animate_sticky`）
   - 原实现幽灵 QLabel 的清理只挂 `anim.finished`：快速连点时 `stop()` 不发射 finished，
     上一轮幽灵截图永久冻结在屏幕上
   - 新增 `_sticky_ghost` 成对引用 + `_cleanup_sticky_anim()`（重启前显式 deleteLater）+
     `_on_sticky_anim_finished()`；动画时长魔法数字（300/500/0.3）提为类常量并改线性插值

2. **进度展开态被刷新重置**（`expanded_view.py` 刷新循环 + `todo_card.expand_progress()`）
   - 原：每次数据刷新 `set_entries` 无条件收起，与 ExpandedView 的展开记录脱节
   - 修复：刷新循环中当前记录为展开中的卡片调 `card.expand_progress()` 恢复（TodoCard 补对称 API）

3. **归档对话框恢复后不刷新**（`archive_dialog.remove_item()` + 控制器接线）
   - 对话框停留在打开时的快照，被恢复条目仍显示，再点"恢复"静默无效
   - 新增 `remove_item(id)`（同步移除卡片+刷新 footer）；控制器通过 lambda 捕获对话框引用回调；
     `restored is None` 分支补"该条目已不在归档中"提示

4. **启动恢复窗口位置无屏幕边界校验**（`main_window.py` `_restore_position`）
   - 换显示器/改分辨率/异常坐标时窗口可能整体落在屏幕外且无找回入口
   - 恢复后用 `screenAt(geometry().center())` 校验，无效则回退默认位置并记日志

5. **桌宠去白底缓存键冲突**（`pet_view.py` `_cache_key()`）

   - 改为 `stem + 来源目录 crc32 指纹 + 扩展名`（跨进程稳定，非随机 hash）

6. **悬空 QMovie 崩溃风险**（`pet_view.py`）
   - `load_pet()` 提前 return 路径下画布持有已 deleteLater 的 QMovie，paintEvent 抛 RuntimeError
   - 新增 `PetCanvas.clear_content()`（_clear_movie 先清画布引用再销毁）+
     `current_pixmap()` 的 RuntimeError 兜底

7. **自定义 tooltip 宽度上限**（`custom_tooltip.py`）
   - 测量/label 上限 4000px → `_MAX_WIDTH = 480`：长标题强制换行，不再横跨屏幕

8. **低危四连**（随触随修）
   - `theme.py`：`body_bold` 字体串补 `bold` 前缀（原本加粗实际不生效）；
